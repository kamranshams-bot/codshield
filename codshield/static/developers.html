CODShield API

Check a cash-on-delivery customer's risk before you ship, and report what happened afterwards. One API for stores, marketplaces and couriers in Pakistan and the UAE.

Overview

Base URL: https://codshield-sx1i.onrender.com. Every path below starts with /v1. Requests and responses are JSON (UTF-8). Times are ISO 8601 in UTC.

Every response carries an X-Request-ID header. Send your own X-Request-ID to correlate logs; quote it when you contact support.

The v1 contract only changes additively: we may add fields and endpoints, never remove or rename them. Ignore fields you don't recognise.

Authentication

Create keys under Developers in the CODShield app (store admins only). Send the key in the X-API-Key header. Keys are shown once; we store only a hash.

Key prefixModeBehaviour
cs_live_…LiveReal network data. Checks count toward your monthly plan.
cs_test_…TestSandbox. Fixed sample answers, validation identical to live, nothing stored, nothing counted.

Each key has one or more scopes:

ScopeAllows
checkPOST /v1/check, POST /v1/check/batch
reportPOST /v1/events, POST /v1/events/batch (contributor tier only)
readGET /v1/reports, GET /v1/usage

Give each system its own key with the fewest scopes it needs, for example a checkout plug-in with check only and a courier sync job with report only. Revoke a key and it stops working immediately.

Quickstart

Check an order before dispatch

curl -X POST BASE/v1/check \
  -H "X-API-Key: $CODSHIELD_KEY" -H "Content-Type: application/json" \
  -d '{"phone": "0300-1234567", "country": "PK"}'
import os, requests

r = requests.post("BASE/v1/check",
                  headers={"X-API-Key": os.environ["CODSHIELD_KEY"]},
                  json={"phone": "0300-1234567", "country": "PK"}, timeout=10)
r.raise_for_status()
risk = r.json()
if risk["band"] == "high":
    ask_for_prepayment()
elif risk["band"] == "medium":
    send_otp_or_call()
const r = await fetch("BASE/v1/check", {
  method: "POST",
  headers: { "X-API-Key": process.env.CODSHIELD_KEY, "Content-Type": "application/json" },
  body: JSON.stringify({ phone: "0300-1234567", country: "PK" }),
});
if (!r.ok) { const { error } = await r.json(); throw new Error(`${error.code}: ${error.message}`); }
const risk = await r.json();   // { score, band, recommended_action, reasons, ... }

Report what happened

curl -X POST BASE/v1/events \
  -H "X-API-Key: $CODSHIELD_KEY" -H "Content-Type: application/json" \
  -d '{"order_ref": "LF-1001", "type": "refused_at_door",
       "occurred_at": "2026-10-14T12:00:00Z", "phone": "0300-1234567",
       "country": "PK", "amount": 4500, "currency": "PKR", "evidence": "TCS:77812"}'
{"index": 0, "outcome": "created", "event_id": 812, "requires_approval": false}

Report paid deliveries too (delivered_paid). They lower a good customer's score and keep the network fair.

Data model: customer identifiers

Requests carry a customer's phone, email and/or address. CODShield normalises each one, then stores only a keyed hash (HMAC-SHA256). Raw values are never stored or returned.

FieldTypeRules
phonestringAny common format: 0300-1234567, +92 300 1234567, 923001234567, 0092…, 050 123 4567, +971…. Normalised to E.164 using country. Strongest identifier.
emailstringLower-cased; +tags removed; Gmail dots ignored.
addressstringLower-cased, punctuation removed, common abbreviations expanded (st → street). Combined with city. Weakest identifier; never enough alone to report.
citystringOptional, improves address matching.
countryenumPK or AE. Default PK for checks, the store's home country for outcomes.

Batch results

Batch endpoints never fail as a whole for bad rows. Each item comes back with its own result, in the order sent.

// POST /v1/events/batch
{"batch_ref": null, "requires_approval": false, "results": [
  {"index": 0, "outcome": "created", "event_id": 913},
  {"index": 1, "outcome": "duplicate", "event_id": 812},
  {"index": 2, "outcome": "rejected", "error": "a valid phone or email is required (address alone is not enough)"}]}

// POST /v1/check/batch
{"results": [{"index": 0, "ok": true, "score": 12, "band": "low", ...},
             {"index": 1, "ok": false, "error": "provide at least one valid phone, email or address"}]}

outcome is one of created, duplicate, pending (waiting for a checker), rejected or test_accepted.

Dispute

Customers can contest records about their number (public, no key: POST /v1/disputes). Contested records stop counting until CODShield decides. Stores whose records are involved get dispute.opened and dispute.resolved webhooks and can withdraw or confirm their records in the app.

FieldTypeMeaning

Webhooks

Add endpoints under Developers → Webhooks. We POST JSON to your HTTPS URL. Respond with any 2xx within 5 seconds. Failures are retried with backoff (2, 4, 8, 16, 32 minutes; 6 attempts in total). Process each id only once, because a retry can repeat an event you already handled.

Verify the signature

Compute HMAC-SHA256 of {t}.{raw body} with your endpoint's signing secret and compare it to v1. Reject requests where t is more than 5 minutes old.

import hashlib, hmac, time

def verify(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    if abs(time.time() - int(parts["t"])) > 300:
        return False
    expected = hmac.new(secret.encode(), f"{parts['t']}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts["v1"])
import crypto from "node:crypto";

export function verify(rawBody, header, secret) {
  const parts = Object.fromEntries(header.split(",").map(p => p.split("=")));
  if (Math.abs(Date.now() / 1000 - Number(parts.t)) > 300) return false;
  const expected = crypto.createHmac("sha256", secret).update(`${parts.t}.`).update(rawBody).digest("hex");
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1));
}

Errors

Every error has the same shape. Branch on error.code, which never changes; show or log error.message; quote error.request_id to support. Validation errors list every bad field at once in error.fields. The older detail field is kept for existing integrations.

Sandbox calls don't count toward monthly checks but do count toward the per-minute rate.

Every API-key response announces the limit, so you can slow down before you hit it: X-RateLimit-Limit (requests a minute), X-RateLimit-Remaining and X-RateLimit-Reset (Unix time the window frees up). A 429 also carries Retry-After in seconds.

Retries are safe. An outcome is stored once per store, order_ref and type; sending it again returns duplicate, so you can retry a timed-out batch without double counting.

Privacy

  • Phone numbers, emails and addresses are hashed on arrival. Names are never accepted.
  • Outcomes are facts ("refused at door"), not opinions. One store alone can never mark someone high risk.
  • Records decay over time and are deleted after two years. Customers can contest any record.
  • Use results to choose a verification step (call, OTP, prepayment). A score must not be the sole reason to refuse service, and results must not be shared outside your business.
